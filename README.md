# Лабораторная работа №3 — ИИ в визуализации данных

**Готовый сайт для GitHub Pages.** Тема — «Успеваемость школьников: траектории оценок, состав групп и распределение итоговых баллов».

## Содержание

Три **разных типа графиков из основного списка** задания (все на одном наборе Student Performance, математика):

1. **Sankey** — переходы категорий оценок G1 → G2 → G3; 3 этапа; ширина лент — число учеников.
2. **Sunburst** — иерархия «школа → время учёбы → итоговая группа».
3. **Beeswarm** — каждое наблюдение как отдельная точка; распределение итогового балла по времени учёбы.

На странице есть вопрос и автоматический вывод для каждого графика, фильтры (школа, пол, учебное время, итоговая категория, максимальные пропуски), сводные показатели, сохранение отфильтрованного CSV и описание методики.

**Важно:** при запуске страница показывает локальный проверенный резервный фрагмент из 91 реальной записи (первые 45 + последние 46 строк исходного CSV) и автоматически пытается подгрузить полный оригинал, после чего показывает статус **«Полный оригинал · 395 записей»**. Если зеркало недоступно, страница продолжает работать на резервном фрагменте и честно обозначает режим. Для полностью автономного сайта без зависимости от зеркала сохраните исходный полный `student-mat.csv` (из UCI) в `data/student-mat.csv` и загрузите этот файл в репозиторий: он получит приоритет над зеркалом.

> Резервный фрагмент — **не репрезентативная выборка** и не должен использоваться вместо полного файла для итоговых выводов. Перед сдачей убедитесь, что над графиками появилась зелёная надпись «Полный оригинал · 395 записей». При необходимости добавьте файл локально в репозиторий, как описано выше.

## Публикация на GitHub Pages — рекомендуемый способ

В архиве уже есть **GitHub Actions**, который при публикации автоматически загружает **полный набор из 395 строк** непосредственно из UCI (с резервом в виде зеркала), проверяет все оценки и кладёт `data/student-mat.csv` внутрь опубликованного сайта. Пользователи сайта не зависят от внешнего источника данных.

1. Создайте **Public** репозиторий, например `lab3-data-visualization`, с веткой `main`.
2. Загрузите **всё содержимое** этой папки в **корень** репозитория, в том числе скрытую папку `.github` (если загружаете через браузер: **Add file → Upload files → Commit changes**). `index.html` должен находиться в корне.
3. Откройте **Settings → Pages → Build and deployment**.
4. В **Source** выберите **GitHub Actions** (НЕ `Deploy from a branch`).
5. Перейдите в **Actions**. Если процесс не запустился после загрузки файлов, откройте `Publish laboratory work to GitHub Pages` → **Run workflow → Run workflow**.
6. Дождитесь зелёной отметки у сборки и вернитесь в **Settings → Pages**: там будет ссылка вида `https://ВАШ_ЛОГИН.github.io/lab3-data-visualization/`.
7. Откройте ссылку в режиме инкогнито и проверьте **«Полный оригинал · 395 записей»**, три графика и работу фильтров. Для сдачи отправьте именно эту публичную ссылку.

Документация: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

**Альтернатива без Actions:** можно опубликовать из ветки `main`, `/ (root)`, однако тогда по умолчанию данные загружаются с публичного зеркала при открытии страницы; если оно недоступно, будет показан резервный фрагмент. Чтобы не зависеть от сети, заранее загрузите полный `data/student-mat.csv` из первоисточника в репозиторий.

Затем откройте http://localhost:8000/ . Для GitHub Pages это **не требуется**.

## Как интерпретируются числа

- `G1`, `G2`, `G3`: первый период, второй период, итоговая оценка (шкала 0–20).
- Группы оценок для анализа: **0–9**, **10–13**, **14–20** (авторская группировка).
- `studytime`: **1** — меньше 2 ч/нед.; **2** — 2–5 ч; **3** — 5–10 ч; **4** — больше 10 ч.
- Sankey считает по одному переходу **G1→G2** и одному **G2→G3** на ученика. Каждый слой содержит то же число учеников.
- Sunburst показывает **число учеников**, а не сумму баллов. Доли в подсказках считаются относительно родительской категории.
- Beeswarm показывает **все отдельные оценки G3**, без случайной подмены значений; горизонтальный сдвиг служит только для того, чтобы точки с одинаковой оценкой не накладывались.
- Метрики/выводы считаются **по текущему отфильтрованному набору**. Связь времени занятий и оценки не означает причинно-следственное влияние.
